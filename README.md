# Сайт ресторана «ФаСоль»: код для встраивания

Статический сайт-главная (HTML, CSS, JavaScript без фреймворков, сборка Vite) и слой оформления для действующего электронного меню. Серверная часть не нужна: сайт читает публичное API меню только на чтение.

## Что внутри

```
index.html                  разметка главной
src/styles/site.css         все стили главной, один файл (порядок правил важен)
src/scripts/                модули главной
  launch-config.js          боевой домен и номер счётчика Метрики — заполнить перед запуском
  cookie-consent.js         баннер cookie, ссылки на политики в подвале, загрузка Метрики после согласия
  site.js                   окна меню, бара, «О нас», навынос
  site-media.js             слайд-шоу фото, галерея, запасной вид карты
  store.js                  витрина навынос и корзина
  menu-api.js               чтение меню из API
  site-bindings.js          настройки сайта из API: телефон, адрес, часы, баннеры
  motion.js                 анимации появления и закрытия окон
  dish-sizes.js             размеры фото блюд
public/                     то, что копируется в сборку как есть
  privacy.html, cookies.html, legal.css   политика конфиденциальности и политика cookie
  img/                      фото и логотипы
  fonts/                    шрифты Cormorant Garamond и Golos Text (OFL) и лицензии
  data/                     снимки меню и настроек — запасной вариант, если API недоступно
emenu/                      слой оформления электронного меню
  fasol/assets/             emenu-redesign.css, emenu-redesign.js
  fasol/fonts/              шрифты и Font Awesome для меню
  fasol/img/                логотип
  laravel/emenu-redesign-head.blade.php   готовый фрагмент подключений
tools/make-seo-files.mjs    robots.txt, sitemap.xml и canonical для боевого домена
package.json, vite.config.js
```

## Как собрать

Нужен Node.js 20.19+ или 22.12+.

```bash
npm ci
npm run build      # результат в dist/
npm run preview    # посмотреть сборку локально
```

`dist/` — готовая статика: `index.html`, `privacy.html`, `cookies.html`, `legal.css`, `assets/` (один JS и один CSS), `img/`, `fonts/`, `data/`. Пути относительные, сборку можно положить в корень домена или в подпапку.

Для боевой сборки после `npm run build`: `node tools/make-seo-files.mjs dist --production` — пишет `robots.txt` и `sitemap.xml`, снимает `noindex` и добавляет canonical в `index.html`, `privacy.html`, `cookies.html`. Домен берётся из `SITE_DOMAIN` в `launch-config.js`; пока он пустой, скрипт останавливается с ошибкой. Без `--production` — закрытый от индексации вариант для превью.

## Как встроить

### а) Сайт-главная

1. Положить содержимое `dist/` на тот же домен, где работает API меню (`/api/...`). Запросы идут по относительным адресам, поэтому другой домен без прокси не подойдёт.
2. Включить рабочий режим. На домене `fasol.orionhall.by` он включается сам. На любом другом — атрибутом на корневом блоке в `index.html`:

```html
<div class="fasol-site design-b" id="fasol-site" data-pickup-discount="0.2"
     data-live-api="true" data-order-url="https://fasol.orionhall.by/">
```

`data-order-url` — адрес электронного меню (по умолчанию `https://fasol.orionhall.by/`). Кнопки «Заказать навынос» ведут на него с разделом: `#breakfast`, `#lunch`, `#main`. `data-assets` — необязательный адрес папки со статикой, если она лежит отдельно от страницы.

3. Перед запуском снять `noindex`: сейчас сайт закрыт от поисковиков. Это делает `make-seo-files.mjs --production` в собранном `dist/` (см. «Как собрать»); вручную — убрать строку `<meta content="noindex,nofollow" name="robots"/>` из `index.html`.

4. Заполнить `src/scripts/launch-config.js` и пересобрать:

```js
export const SITE_DOMAIN = 'https://ваш-домен.by'   // с https://, без слэша в конце
export const METRIKA_ID = '12345678'                // номер счётчика Яндекс Метрики, строкой
```

Пока `SITE_DOMAIN` пустой, сайт считает себя превью: баннер cookie не показывается и Метрика не загружается ни на каком домене. На домене из `SITE_DOMAIN` баннер появляется при первом визите, счётчик подгружается только после «Принять» и только если `METRIKA_ID` не пустой. Код счётчика в `<head>` не ставить: он начнёт работать до согласия, в обход баннера. `PRIVACY_EMAIL` и `SITEMAP_PATHS` читает `make-seo-files.mjs`; e-mail в `privacy.html` и `cookies.html` уже вписан текстом.

Чтобы посмотреть баннер на превью до запуска, добавьте к адресу `?cookie-banner=1`. Ключ `--domain=` у `make-seo-files.mjs` нужен только для проверочной сборки на другом адресе.

Ссылки «Политика конфиденциальности» и «Политика cookie» добавляются в подвал на любом домене и ведут на `privacy.html` и `cookies.html` рядом со страницей.

#### Перед запуском на своём домене

Без `data-live-api="true"` на корневом блоке (п. 2) на любом домене, кроме `fasol.orionhall.by`, включается демо-корзина: гость оформляет заказ, видит «Заказ принят», но заказ никуда не уходит. Перед открытием проверьте атрибут в собранном `dist/index.html` и что кнопки «Заказать навынос» ведут в электронное меню, а не в корзину на странице.

### б) Слой оформления электронного меню

1. Скопировать `emenu/fasol/` в `public/fasol/` приложения меню. Существующие файлы не перезаписываются.
2. На `<html>` шаблона меню (не админки) добавить маркер. Слой ставит его и сам после загрузки скрипта, но с маркером в разметке стили применяются сразу и страница не мигает исходным видом:

```html
<html lang="ru" data-emenu-redesign="fasol" data-fasol-assets="/fasol/" data-fasol-home="/restaurant">
```

`/restaurant` — пример, заменить адресом новой главной.

3. В конце `<head>`, после существующих Bootstrap, `/css/emenu.css` и встроенного `<style>`:

```html
<link rel="stylesheet" href="/fasol/fonts/fonts.css">
<link rel="stylesheet" href="/fasol/assets/emenu-redesign.css?v=4bcae7ffb2">
<script defer src="/fasol/assets/emenu-redesign.js?v=4bcae7ffb2"></script>
```

Тот же фрагмент через `asset()` — в `emenu/laravel/emenu-redesign-head.blade.php`.

Слой не делает запросов к API, не трогает вход, AppState, расчёт корзины и отправку заказа; `main.js`, модули, ID элементов и Bootstrap-окна остаются вашими. Все стили, кроме подключаемого `fontawesome.css`, ограничены селектором `[data-emenu-redesign="fasol"]`. На страницах с `body.admin-page` и без `#app-container` скрипт ничего не делает.

Кроме оформления, слой вмешивается в поведение меню в трёх местах (`emenu/fasol/assets/emenu-redesign.js`):

1. **Кнопки «В заказ» по расписанию.** Вне часов ветки (см. ниже) кнопки `.add-to-cart-btn`, `.add-to-cart-from-modal-btn` и `#addItemToCartBtn` получают `disabled` и подпись с часами. Клик по ним перехватывается на `document` (`preventDefault` и `stopImmediatePropagation`), ваш обработчик добавления не вызывается. Когда ветка открывается, исходное состояние кнопки возвращается. Это ограничение только в интерфейсе: сервер должен сам проверять расписание при оформлении.
2. **Атрибут `data-folder-code` у разделов чужих веток.** Подсветка разделов при прокрутке в `ui.js` идёт по `.folder-dishes-section[data-folder-code]`, включая скрытые слоем. Поэтому у разделов других веток атрибут переносится в `data-fasol-folder-code` и возвращается при смене ветки. Если ваш код ищет разделы по `data-folder-code`, разделы скрытых веток он не увидит.
3. **Автоклик по категории.** Слой читает раздел из адреса (`#breakfast`, `#lunch`, `#main`) и сам нажимает первую непустую категорию ветки (завтраки 7855, обеды 5497, основное 5222). Если категория не стала активной, клик повторяется до 8 раз с интервалом 250 мс. Остальные ветки скрываются оформлением. Без раздела в адресе слой ничего не нажимает и ветки не скрывает.

Отключить слой целиком — убрать строку `<script>` с `emenu-redesign.js` (вместе с ней маркер и две строки CSS). Одного снятия маркера мало: скрипт выставит его заново.

**Данные, продублированные в слое.** Расписание вынесено в начало `emenu-redesign.js`: `scheduleRoots` — 26 кодов папок и их ветка, `rootSchedule` — часы подачи для подписей (`label`, `hours`) и время приёма заказов (`start`, `end`). Подача: завтраки пн–пт 9:00–12:00, сб–вс 10:00–12:00; обеды пн–пт 12:00–15:00; основное ежедневно 12:00–23:00. Приём навынос заканчивается в 11:55, 14:55 и 22:35, после этого кнопки «В заказ» неактивны. Слой эти данные из `config.js` и API не берёт. Если в админке поменяются часы или появится новая папка, поправьте и этот объект, иначе слой будет закрывать кнопки по старому времени, а новую папку не отнесёт ни к одной ветке.

**Запасные значения.** Если `#venue-address-text-desktop` или `#venue-hours-text-desktop` пусты, слой подставляет «г. Гомель, ул. Советская, 36» и «Пн–Пт 09:00–23:00 · Сб–Вс 10:00–23:00». Категория с названием `null` показывается как «Другие блюда», папка 9105 — как «Десерты обеда»: в ваших данных у папки 9105 имя `null` (на 19.11.2026), стоит заполнить его в админке.

**Иконки.** Если на странице нет элемента с `[data-fasol-icons]`, слой сам подключает `fasol/fonts/fontawesome.css` (Font Awesome 6, woff2). Если вы подключаете свой Font Awesome, пометьте его `<link>` атрибутом `data-fasol-icons`, чтобы не грузить второй набор.

### в) Правка `modules/config.js`: разделы видны вне своего времени

Без правки по ссылке `#breakfast` днём гость увидит заголовок раздела, но не блюда: сервер не отдаёт папку вне расписания. Нужно, чтобы блюда были видны, а кнопка «В заказ» неактивна. Добавить по одной строке первой в двух функциях:

```js
    // ...дальше без изменений
```

```js

    if (/^#(breakfast|lunch|main)$/.test(window.location.hash)) return true;

```

Коды корневых папок 6846 (завтраки), 5474 (обеды), 5139 (основное) взяты из публичного API — сверьте с базой. Без раздела в адресе меню ведёт себя как раньше. Запрет оформления вне времени (`isVenueClosedForOrders`) не затрагивается. Правила по отдельным блюдам (суп дня и т. п.) остаются.

**Авторство.** Ссылка «Сайт — Елена Саманчук» в подвале, `<meta name="author">` в `index.html`, `privacy.html`, `cookies.html`, комментарий в начале `index.html` и `public/humans.txt` — подпись разработчика. Пожалуйста, не удаляйте их при встраивании.

## Что настроено с нашей стороны

**Чтение API (только GET, без авторизации).** В рабочем режиме главная запрашивает:

- `/api/site/config` — телефон, адрес, часы работы, e-mail, юр. данные, основной цвет, баннеры;
- `/api/menu/list` — код электронного меню;
- `/api/menu/dish/list?menu_id=…&parent_id=…` — блюда по папкам веток 5139, 6846, 5474 (не больше 39 запросов, тайм-аут 8 с).

Учитываются `hidden_folder_codes`, `hidden_dish_codes`, `is_bot_export`, `in_stop_list`. Цены, фото, КБЖУ и вес берутся из ответа.

Заголовок вкладки и описание для поиска заданы в `index.html` (`<title>`, `meta description`, `og:*`) и из API не берутся: в настройках сейчас `site_title`, `meta_title` и `venue_name` набраны как «ФаCоль» с латинской C, а в `meta_description` указан адрес ул. Крестьянская, 16 вместо Советской, 36. Если поправите настройки, эти строки в `index.html` можно оставить как есть.

**Запасной вариант.** Если API не ответило, сайт показывает снимки `public/data/site-config-snapshot.json` и `public/data/menu-snapshot.json`. Барная карта (`printed-menu.json`) — без цен, для ознакомления.

**Заказ навынос и формы.** В рабочем режиме главная заказы не оформляет: три кнопки выбора меню ведут в ваше электронное меню, оформление и отправка — там. Вне рабочего режима (демо на чужом домене) открывается демо-корзина: гость видит обычное оформление и экран «Заказ принят», но данные никуда не отправляются, остаются в браузере. Других форм на сайте нет: бронь, сертификаты и вакансии — по телефону.

## Что за вами

- Домен и размещение сборки рядом с API.
- Боевой домен и номер счётчика Яндекс Метрики в `src/scripts/launch-config.js` (см. «Как встроить», п. 4). Метрика на главной подключается только через этот файл, после согласия на cookie; в шаблон электронного меню слой счётчик не ставит.
- `robots.txt` и `sitemap.xml` на боевом домене: `node tools/make-seo-files.mjs dist --production` после сборки.
- Приём заказов: оформление и отправка идут через ваше электронное меню. Подключение демо-корзины главной к вашему приёму заказов, если оно понадобится, — за вами.
- Фото, цены, состав, стоп-лист, баннеры и контакты — в вашей админке, сайт подтягивает их сам. Фото разделов и интерьера лежат в `public/img/`, их замена — правкой файлов.
- Время приёма навынос в админке: завтраки до 11:55, обеды до 14:55, основное меню до 22:35. Сайт показывает «Принимаем заказы до 11:55 / 14:55 / 22:35» и закрывает кнопки по этому времени. В вашей системе сейчас у основного меню (папка 5139) окончание 22:55 — поменяйте на 22:35, иначе электронное меню будет принимать заказы ещё 20 минут после того, как сайт их закрыл.
- Часы веток и коды папок в `emenu-redesign.js` — менять вместе с админкой. Имя папки 9105 в админке.
- Проверка на вашей тестовой копии: вход, оформление заказа и отправка, правка `config.js`, окончание приёма по расписанию.
